# 领域文档

BlogSite 使用单上下文布局。探索代码前，先读根目录的 `GLOSSARY.md`，并查阅 `docs/adr/` 下与本次工作相关的架构决策记录（ADR）。文件尚未建立时，直接继续任务。

- 在工单、规格、重构提议和测试名称中沿用术语表的用词。遇到未收录的概念，先核对仓库现有用语。术语达成共识后，由 `domain-modeling` 记入术语表。
- 方案与现有 ADR 冲突时，指出决策编号、冲突点和重新讨论的理由。新架构决策确定后，再在 `docs/adr/` 建立记录。
- 发布字段、枚举、默认值和 manifest 版本以 `contracts/publishing/` 为准。
