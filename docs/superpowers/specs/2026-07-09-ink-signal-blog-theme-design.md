# Ink & Signal 博客主题设计

## 目标与边界

本次改造只作用于 BlogSite 的公开展示层。保留 `blog`、`notes`、`projects`
三个内容集合及其 frontmatter、URL 和排序语义；不读取或修改 Obsidian Vault，
不改 Vault 同步、双链转换、发布检查和 manifest 逻辑。

目标是把当前通用卡片式主题收敛为适合中文技术写作与公开知识库的阅读界面：
首页先建立站点定位，再引导到最近内容；列表便于扫描；详情页优先保证长文、
代码、表格和目录的连续阅读。

## 现状审查

- `src/styles/global.css` 只定义了颜色、单一圆角、单一阴影和部分间距。
  字号、行高、圆角、阴影、控件高度、代码块样式仍散落为裸值。
- 深色调色板在媒体查询和 `[data-theme="dark"]` 中重复维护。
- 卡片悬浮阴影和搜索遮罩使用独立颜色值，没有进入 token。
- 首页三个集合采用完全相同的卡片权重，无法突出最近博客与最近更新。
- 内容列表可读，但日期、分类、标题、摘要和标签的层级差异较弱。
- 文章页已有目录、阅读进度和首个 H1 去重，应保留这些行为并优化排版。
- 缺少标签聚合页和自定义 404 页。

## 方案比较与选择

1. **Ink & Signal（采用）**：以纸墨和蓝青信号色表达“本地知识经过筛选后公开”
   的内容流。辨识度来自首页索引轨道和标题字体，其他位置保持安静。
2. **Ocean Depths**：延续当前蓝色卡片主题，迁移成本最低，但与通用开发者博客
   辨识度接近。
3. **Modern Minimalist**：进一步减少装饰，维护简单，但容易弱化三个内容集合的
   信息结构。

## 自定义主题

### 颜色

所有颜色只在 `src/styles/tokens.css` 定义。组件、布局、页面和
`global.css` 只能引用 token 或使用 token 参与 `color-mix()`。

Light：

- Paper `#F5F8F7`：页面底色
- Sheet `#FFFFFF`：抬升表面
- Ink `#152225`：正文与标题
- Slate `#5B6B6E`：次要文本
- Signal `#087F8C`：链接、焦点和阅读进度
- Signal Deep `#075E68`：强调交互状态

Dark：

- Paper `#091113`
- Sheet `#101A1D`
- Ink `#EDF5F3`
- Slate `#A7B8B6`
- Signal `#65D1CF`
- Signal Deep `#A0E4E0`

边框、弱表面、遮罩、选区、状态色和阴影由上述主题色或专用 token 派生，
不在规则中写一次性颜色。

### 字体

- 展示标题：`ui-serif`、`Iowan Old Style`、`Songti SC`、`STSong`。
  只用于首页主标题、页面标题和文章标题，提供知识出版物的识别度。
- 正文：`Inter`、`Noto Sans SC` 和系统无衬线栈，保证中文长文清晰。
- 元数据与代码：`SFMono-Regular`、`Cascadia Code` 和系统等宽栈，
  用于日期、分类、标签、目录标记和代码。

字号使用 `--text-xs` 到 `--text-5xl` 的流体比例；正文、紧凑、标题和代码
分别使用明确的行高 token。

### 空间与形状

- 使用从 `0.25rem` 到 `6rem` 的间距比例，不在组件规则中出现重复裸间距。
- 正文最大宽度为约 43rem，长行不跨越整个宽屏。
- 圆角分为小、中、大和胶囊四级。卡片使用中圆角，代码块使用小圆角，
  标签使用胶囊圆角。
- 阴影分为浮层和悬浮两级。普通内容区主要靠边框和留白建立层级，
  不把页面做成 dashboard。

### 代码

内联代码和代码块分别使用 `--code-*` 语义 token。代码块提供独立表面、
边框、前景色、选区色、字号、行高和横向滚动空间；不会引入新的高亮依赖。

## 页面结构

### 全局导航

桌面端保持单行导航，增加“标签”入口。移动端保持当前可换行结构，但把搜索与
主题切换作为紧凑图标文字控件。主题脚本继续在首屏样式计算前运行，使用
`color-scheme` 与 `light-dark()` 让系统主题和手动主题共用一份调色板定义。

### 首页

首页不再使用三个同权卡片。结构为：

```text
┌───────────────────────┬──────────────────────┐
│ 站点定位与主标题       │ 最近更新 / 日期 / 类型 │
│ 简短说明 + RSS         │ 最近三条公开内容        │
└───────────────────────┴──────────────────────┘

BLOG  ── 最新长文标题、摘要、日期
NOTES ── 最近笔记列表
PROJECTS ── 最近项目列表
```

“索引轨道”使用集合名、细线和真实条目数量编码内容结构，是本主题唯一的醒目
结构特征。它不是装饰性编号，也不使用统计面板或营销卡片。

### 内容列表

每条内容使用编辑式分隔线而不是封闭卡片。日期和分类位于左侧或上方的等宽
元数据区，标题与摘要承担主层级，标签链接到标签页对应分组。移动端改为单列。

### 文章详情

保留文章目录、阅读进度、发布时间、更新时间、系列和主题字段。标题区与正文
使用同一阅读轴；桌面目录位于右侧，平板和移动端移到正文之前。正文强化中文
段落间距、列表层级、引用、表格、图片、内联代码和代码块。

### 标签页

新增 `/tags/` 聚合页面。按标签名称排序，每个标签显示公开内容数量和对应条目，
使用页面内锚点支持从列表标签直接跳转。它不新增内容集合，也不改变 URL slug。

### 404 页

新增静态 `404.astro`。使用简短说明、返回首页和浏览博客两个明确动作，不加入
插画依赖或与站点无关的文案。

## 响应式与无障碍

- 验证宽度为 390px、768px、1440px。
- 保留跳转正文链接、键盘焦点、语义标题顺序和搜索 dialog。
- 交互触控目标不小于 40px。
- `prefers-reduced-motion: reduce` 时关闭平滑滚动、悬浮位移和非必要过渡。
- Light/dark 两种模式均检查正文、链接、边框、代码块和搜索浮层对比度。

## 测试与验收

- 扩展 `tests/theme-render.test.ts`，先验证 token 结构、页面存在性、标签聚合、
  颜色边界和保留的文章行为。
- 运行 `pnpm test`、`pnpm check:publish`、`pnpm build`。
- 使用 `webapp-testing` 的 `with_server.py` 启动构建预览，用 Playwright 在
  390px、768px、1440px 截取首页、列表、文章、标签和 404 的 light/dark 页面。
- 检查浏览器控制台错误、横向溢出、主题切换、搜索打开/关闭和标签跳转。
- 截图存放到 `output/playwright/ink-signal/`，变更报告写入
  `docs/theme-optimization-report.md`。

## 不改动的部分

- `scripts/` 下的 Vault 同步、Markdown 归一化、资源复制和发布检查。
- `src/content.config.ts` 的字段及三个内容集合。
- `src/content/**` 的公开正文与 frontmatter。
- 双链转换、manifest、RSS 数据生成和 GitHub Actions 发布流程。
