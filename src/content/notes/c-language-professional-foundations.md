# C语言专业级基础知识汇总

## 适用范围

这篇笔记按 C11/C17 语义组织，目标不是重讲语法，而是恢复以下能力：

- 准确判断一段代码是标准定义、实现定义、未指定还是未定义。
- 在时间压力下识别类型转换、对象生命周期、指针、字符串和内存管理风险。
- 写出对编译器优化成立的代码，而不是只在某组输入或 `-O0` 下“看起来能跑”。
- 区分 ISO C、POSIX、编译器扩展和特定 ABI 的能力边界。

## 先建立四层判断

### 标准定义行为

所有符合要求的实现都必须满足标准规定。考试答案应尽量建立在这一层。

### 实现定义行为

实现可以选择，但必须记录其选择。例如 C17 中负的有符号整数右移结果、普通 `char` 是有符号还是无符号。

### 未指定行为

实现可以从多个允许结果中选择，通常不要求记录。例如函数实参的求值顺序。

### 未定义行为

标准不施加要求。编译器可以假设它永远不会发生，并据此删除、合并或重排代码。典型例子包括有符号整数溢出、越界访问、未初始化自动对象读取和错误格式说明符。

不要把“我的机器输出了某个值”当作未定义行为的解释。

## 翻译过程、声明和链接

### 从源文件到程序

常见阶段是预处理、编译、汇编、链接。语言标准描述翻译阶段；具体命令和目标文件格式属于实现或平台。

- 预处理处理 `#include`、宏和条件编译。
- 每个 `.c` 文件连同展开的头文件形成一个翻译单元。
- 编译器分别处理翻译单元，链接器解析具有链接属性的符号。
- 头文件通常放声明、类型定义、宏和 `static inline` 函数，不放普通外部定义。

### 声明、定义和暂定定义

```c
extern int global_count;  /* 声明，不分配当前定义 */
int global_count = 0;     /* 定义 */
int cache_size;           /* 文件作用域暂定定义 */
```

函数原型必须写完整：

```c
int parse(const char *text); /* 有原型 */
int legacy();                /* 参数未指定，不等于无参数 */
int no_args(void);           /* 明确无参数 */
```

### 作用域、链接、存储期是三组不同概念

- 作用域决定名字在源代码哪里可见。
- 链接决定不同声明是否指向同一实体。
- 存储期决定对象的生命周期。

文件作用域的 `static` 对象或函数具有内部链接：

```c
static int cache[128];
static int helper(int x);
```

头文件中的小函数通常使用：

```c
static inline int max_int(int a, int b)
{
    return a > b ? a : b;
}
```

C 的外部 `inline` 规则与 C++ 不同且容易受编译模式影响。机考和普通项目中，头文件辅助函数优先使用 `static inline`。

## 整数类型和转换

### 类型宽度不要凭平台印象

标准只规定最小范围和相对关系，不保证：

- `int` 一定为 32 位。
- `long` 一定为 64 位。
- 指针能放进 `unsigned long`。
- 普通 `char` 是有符号类型。

需要精确宽度时使用 `<stdint.h>`；需要表达对象大小和指针差时分别使用 `size_t` 和 `ptrdiff_t`。

常用格式：

| 类型 | `printf` |
|---|---|
| `size_t` | `%zu` |
| `ptrdiff_t` | `%td` |
| `intmax_t` | `%jd` |
| `uint64_t` | `PRIu64` 宏 |
| `int64_t` | `PRId64` 宏 |

精确宽度类型是可选类型：只有实现存在恰好相应宽度、且无 padding 的整数类型时才提供。

### 整数提升

等级低于 `int` 的整数类型通常先提升为 `int`；如果 `int` 无法表示其全部值，则提升为 `unsigned int`。

```c
unsigned char a = 200;
unsigned char b = 100;
int sum = a + b; /* 两个操作数先提升为 int */
```

这意味着：

- `char`、`signed char`、`unsigned char`、`short` 的算术通常在 `int` 中进行。
- 位运算前也会发生整数提升。
- `~small_unsigned` 的结果类型通常是 `int`，不是原来的小无符号类型。

### 通常算术转换

混合整数运算会寻找共同类型。最危险的场景是有符号数和无符号数混合：

```c
int x = -1;
unsigned int y = 1;

if (x < y) {
    /* 在常见 32 位 int 实现上通常不会进入 */
}
```

比较前，`x` 可能转换为很大的无符号值。解决方式不是记住某个平台结果，而是避免无意义的符号混用，并在转换前检查范围。

### 溢出和除法

- 无符号整数运算按 `2^N` 取模。
- 有符号整数溢出是未定义行为。
- `INT_MIN / -1` 和相应余数操作无法在 `int` 表示时是未定义行为。
- 从更宽整数窄化到有符号类型，如果值不可表示，结果由实现定义或产生实现定义信号。

安全加法的基本形式：

```c
bool add_int_checked(int a, int b, int *out)
{
    if ((b > 0 && a > INT_MAX - b) ||
        (b < 0 && a < INT_MIN - b)) {
        return false;
    }
    *out = a + b;
    return true;
}
```

### 移位

在 C11/C17 中：

- 移位量为负，或不小于提升后左操作数的位宽，行为未定义。
- 负的有符号数左移，行为未定义。
- 非负有符号数左移后结果不可表示，行为未定义。
- 负的有符号数右移是实现定义行为。
- 无符号右移补零；无符号左移按类型宽度处理。

需要位模式时使用无符号类型：

```c
uint32_t mask = UINT32_C(1) << bit;
```

## 表达式和求值顺序

### 优先级不等于求值顺序

括号决定分组，通常不决定函数实参先算哪一个。

```c
f(i++, i++); /* 两次修改之间无顺序保证，存在未定义行为 */
```

典型错误：

```c
a[i] = i++;       /* 对 i 的访问与修改没有适当顺序 */
i = i++ + 1;      /* 未定义行为 */
printf("%d %d", i++, i++); /* 未定义行为 */
```

提供顺序保证的常见运算包括：

- `&&`：左操作数先求值，必要时才求右侧。
- `||`：左操作数先求值，必要时才求右侧。
- `?:`：条件先求值，只求一个分支。
- 逗号运算符：左侧完成后再求右侧。

函数调用前所有实参求值都会完成，但各实参之间的顺序通常未指定。

### 短路求值用于守卫

```c
if (ptr != NULL && ptr->ready) {
    /* 安全访问 */
}
```

不要把按位运算符 `&`、`|` 当成逻辑运算符使用；它们不短路。

## 对象、值类别和生命周期

### 对象不是“变量”的同义词

对象是一块具有类型、大小、对齐和存储期的数据存储区域。字符串字面量、数组元素、结构体成员和动态分配区域都涉及对象语义。

### 左值与可修改左值

左值标识一个对象，但不一定可修改：

```c
const int answer = 42;
/* answer 是左值，但不是可修改左值 */
```

数组表达式在多数上下文转换为首元素指针，但数组对象本身不是可赋值对象。

### 存储期

- 自动存储期：通常是块内普通局部对象，离开块后生命周期结束。
- 静态存储期：程序整个运行期存在，包括文件作用域对象和块内 `static`。
- 线程存储期：每个线程一份，需要相应语言和实现支持。
- 分配存储期：由分配函数开始，`free` 或成功的 `realloc` 结束。

返回局部数组地址是悬空指针：

```c
int *bad(void)
{
    int local[4];
    return local;
}
```

### 初始化

- 静态存储期对象在程序启动前完成零初始化。
- 未显式初始化的自动对象具有不确定值，读取可能产生未定义行为。
- `malloc` 返回的存储内容不初始化。
- `calloc` 将分配的所有字节置零，但“全零字节”不应被泛化成所有类型的语义零值保证。

## 指针与数组

### 数组退化的例外

数组表达式在多数上下文转换为指向首元素的指针，但以下场景不会做普通退化：

- 作为 `sizeof` 的操作数。
- 作为一元 `&` 的操作数。
- 用字符串字面量初始化数组。
- 其他由对应标准版本明确规定的少数上下文。

```c
int a[10];

sizeof a;    /* 整个数组的字节数 */
sizeof &a;   /* 数组指针的大小 */
```

函数形参中的数组写法会调整为指针：

```c
void f(int a[10]); /* 实际参数类型为 int * */
```

因此在 `f` 内部使用 `sizeof a / sizeof a[0]` 得不到调用方数组长度。

### 多维数组参数

除第一维外，编译器需要知道步长：

```c
void process(size_t rows, size_t cols, int a[rows][cols]);
```

VLA 支持在 C11 中成为条件特性，部分编译器或考试环境可能禁用。最保守的接口是传平坦数组和显式列数：

```c
int value = data[row * cols + col];
```

### 指针算术边界

指针算术只在同一数组对象及其尾后一位置内有定义：

- 可以形成 `&a[n]`。
- 不能解引用 `&a[n]`。
- 不应比较或相减来自无关对象的指针来推断地址关系。
- 已释放对象的指针不能再用于访问；复制出来的别名同样悬空。

### `void *`

对象指针可以与 `void *` 相互转换并正确往返。标准 C 不允许直接对 `void *` 做算术；那是常见编译器扩展。

函数指针和对象指针不是可移植地可互换的类型。

### `const` 的位置

```c
const int *p;       /* 指向只读 int，p 可改 */
int *const p2 = q;  /* p2 不可改，所指 int 可改 */
const int *const p3 = q; /* 两者都不可通过该声明修改 */
```

把实际定义为 `const` 的对象强制转换后写入，行为未定义。`const` 不是运行时只读内存的完整模型，但它是类型系统契约。

## 有效类型、别名和对齐

编译器可以假设不兼容类型的指针通常不会指向同一对象，这就是严格别名优化的基础。

危险写法：

```c
float value = 1.0f;
uint32_t bits = *(uint32_t *)&value; /* 违反可移植别名规则 */
```

查看对象表示时使用字符类型，或用 `memcpy` 在同尺寸对象之间复制：

```c
uint32_t bits;
_Static_assert(sizeof bits == sizeof value, "unexpected float size");
memcpy(&bits, &value, sizeof bits);
```

还要满足对齐要求。把任意字节地址强转为更严格对齐类型并解引用，可能产生未定义行为。

考试中遇到“网络包/磁盘格式直接强转结构体”的代码，要同时检查：

- 对齐。
- 大小端。
- 结构体 padding。
- 严格别名。
- 输入缓冲区长度。

## 字符、字符串和缓冲区

### 字符串是以空字符结尾的字符序列

```c
char a[] = "abc";       /* 4 字节，可修改数组 */
const char *p = "abc";  /* 指向字符串字面量，不得修改 */
```

字符串字面量不应通过指针修改。缺少 `'\0'` 的字符数组不能传给要求 C 字符串的函数。

### `strlen` 不含终止符

分配副本时需要 `len + 1`，并检查加法是否溢出：

```c
size_t len = strlen(src);
if (len == SIZE_MAX) {
    return NULL;
}

char *copy = malloc(len + 1);
if (copy != NULL) {
    memcpy(copy, src, len + 1);
}
```

### `memcpy` 与 `memmove`

- 源和目标不重叠时使用 `memcpy`。
- 可能重叠时使用 `memmove`。
- `memcmp` 比较对象表示，不等价于所有结构化值的语义比较。
- 含 padding 的结构体不能用 `memcmp` 可靠判断逻辑相等。

### `EOF` 和字符分类

`getchar`、`fgetc` 返回 `int`，以同时表示所有 `unsigned char` 值和 `EOF`：

```c
int ch;
while ((ch = getchar()) != EOF) {
    unsigned char uch = (unsigned char)ch;
    /* use uch with isalpha/isdigit/... */
}
```

将负的普通 `char` 直接传给 `<ctype.h>` 分类函数，且该值不是 `EOF`，行为未定义。

## 标准 I/O

### 格式说明符必须匹配真实类型

可变参数不会提供足够类型信息修正错误格式。格式与实参类型不匹配可能是未定义行为。

```c
size_t n = 10;
printf("%zu\n", n);
```

`scanf` 接收的是目标对象指针，格式必须匹配目标类型：

```c
long long value;
if (scanf("%lld", &value) != 1) {
    /* handle invalid input */
}
```

### `%s` 宽度

```c
char word[32];
if (scanf("%31s", word) != 1) {
    /* handle input failure */
}
```

宽度不包含自动附加的 `'\0'` 所需位置，因此缓冲区为 32 时使用 31。

### `fgets` 的边界

`fgets` 最多读取 `cap - 1` 个字符并补终止符；如果缓冲区放不下整行，下一次读取会继续该行。是否需要丢弃剩余字符由输入协议决定。

### `snprintf`

返回值表示“如果空间足够，本应写入的字符数”，不含终止符。返回值非负且不小于容量时发生截断：

```c
int written = snprintf(buf, cap, "%s:%d", host, port);
if (written < 0 || (size_t)written >= cap) {
    /* encoding error or truncation */
}
```

## 动态内存

### 分配大小

优先写：

```c
int *a = malloc(n * sizeof *a);
```

而不是重复类型名。类型变化时不容易留下错误。但仍必须检查 `n * sizeof *a` 是否溢出。

### `malloc`、`calloc`、`realloc`

- `malloc` 分配未初始化存储。
- `calloc` 接收元素数量和元素大小，并把分配字节置零；实现有机会检测乘法溢出。
- `realloc` 可能原地扩展，也可能移动。
- `realloc` 成功后，旧对象生命周期结束，应只使用返回的新指针。
- `realloc` 失败时原对象仍有效。

错误：

```c
ptr = realloc(ptr, new_size); /* 失败时丢失原指针 */
```

正确：

```c
void *tmp = realloc(ptr, new_size);
if (tmp == NULL && new_size != 0) {
    /* ptr 仍有效 */
} else {
    ptr = tmp;
}
```

零大小分配在不同标准版本和实现中有细节差异。考试代码最好显式处理零元素，不依赖 `malloc(0)` 或 `realloc(p, 0)` 的具体结果。

### `free`

- `free(NULL)` 安全且无效果。
- 重复释放、释放非分配函数返回的地址、释放对象内部地址均为未定义行为。
- `free` 后把某个指针设为 `NULL` 不会清除其他别名。

### 所有权约定

对每个动态对象回答：

1. 谁创建？
2. 谁拥有？
3. 谁释放？
4. 借用指针可以活到什么时候？
5. 失败路径是否保持原所有权？

这比“最后统一看看有没有 `free`”更可靠。

## 结构体、联合、枚举和位域

### 结构体布局

- 成员按声明顺序排列，后一个成员地址不早于前一个。
- 成员之间和结构体末尾可能有 padding。
- `sizeof(struct T)` 包含尾部 padding，以保证数组元素对齐。
- 不同 ABI、编译选项和成员顺序可能产生不同布局。

可通过 `<stddef.h>` 的 `offsetof` 获取成员偏移，不应手算。

优化内存时通常将高对齐成员放在前面能减少 padding，但不能替代对目标 ABI 的验证。

### 指定初始化

```c
struct Config {
    int timeout;
    bool enabled;
};

struct Config cfg = {
    .timeout = 30,
    .enabled = true
};
```

指定初始化比依赖成员顺序更稳健；未列出的成员按静态初始化规则置零。

### 柔性数组成员

```c
struct Packet {
    size_t length;
    unsigned char data[];
};
```

柔性数组必须是结构体最后一个成员，结构体还必须有至少一个其他命名成员。分配时检查加法：

```c
if (payload_len > SIZE_MAX - sizeof(struct Packet)) {
    return NULL;
}
struct Packet *p = malloc(sizeof *p + payload_len);
```

### 联合

联合成员共享存储。使用联合做类型重解释涉及标准版本、有效类型和实现行为细节；需要可移植位表示转换时优先使用 `memcpy`。

### 枚举

C17 中枚举与某个能表示其成员值的整数类型兼容，具体选择具有实现相关性。不要假设枚举对象一定与 `int` 同尺寸，也不要把任意整数自动视为有效业务枚举值。

### 位域

位域的分配顺序、容器边界、某些类型的有符号性和布局高度依赖实现。它适合与明确 ABI 绑定的代码，不适合作为可移植协议序列化格式。

不能取得位域的地址，也不能对位域使用 `sizeof`。

## 类型限定符

### `const`

表达通过该左值不修改对象的约束。它不自动提供线程安全，也不保证对象一定存放在只读内存。

### `volatile`

`volatile` 要求实现按抽象机规则保留相关访问，典型用途包括内存映射 I/O、某些信号交互和实现定义环境。

它不保证：

- 原子性。
- 多线程可见性协议。
- 互斥。
- 复合操作不可分割。

多线程同步应使用 `_Atomic` 和标准内存模型，或平台同步原语。

### `restrict`

`restrict` 是对某段执行期间访问路径的承诺，允许编译器假设相关对象不会通过不允许的别名访问。违反承诺可能导致未定义行为。

```c
void add(size_t n,
         int *restrict out,
         const int *restrict a,
         const int *restrict b);
```

只有能证明调用方满足不别名条件时才使用，不能把它当作普通性能装饰。

### `_Atomic`

原子对象解决数据竞争和可见性问题，但仍需要正确选择内存顺序和算法。普通对象上的数据竞争是未定义行为；`volatile` 不能修复。

## 预处理器

### 带参数宏

参数和整体表达式都加括号：

```c
#define SQUARE(x) ((x) * (x))
```

但它仍会重复求值：

```c
SQUARE(i++); /* 错误：副作用发生多次 */
```

可用 `static inline` 函数替代时优先使用函数。

### 多语句宏

```c
#define SWAP_INT(a, b)        \
    do {                      \
        int tmp_ = (a);       \
        (a) = (b);            \
        (b) = tmp_;           \
    } while (0)
```

这个宏仍要求参数是可修改左值，并可能与复杂表达式的副作用交互。考试中若无需泛型，直接写函数更清晰。

### 条件编译

区分“宏是否定义”和“宏值是否为真”：

```c
#ifdef FEATURE
#endif

#if FEATURE
#endif
```

头文件应有 include guard 或使用实现广泛支持的 `#pragma once`。最可移植形式是 include guard。

## 标准库高频边界

### 排序和查找

- `qsort` 比较函数要形成一致的顺序关系。
- 比较器返回负、零、正，不要求返回 `-1/0/1`。
- `bsearch` 需要数组已经按相同比较规则排序。
- 比较器通过 `void *` 接收对象地址，转换到正确类型后读取。

### 字符串转数字

相比 `atoi`，`strtol`/`strtoll` 能报告：

- 没有发生转换。
- 尾部非法字符。
- 超出范围。
- 实际停止位置。

解析无符号数时要额外决定是否接受前导负号；库函数的语义不一定等于业务输入协议。

### 时间与随机数

- `rand()` 的质量和范围不适合安全用途。
- `clock()` 测量的是实现定义的处理器时间语义，不等于高精度墙钟。
- 考试题只需按题目要求使用；不要把平台经验当 ISO C 保证。

## 常见未定义行为清单

- 有符号整数溢出。
- 除以零，或不可表示的有符号除法。
- 非法移位量、负数左移、不可表示的有符号左移。
- 数组越界或解引用尾后指针。
- 解引用空指针、悬空指针、无效对齐指针。
- 读取未初始化自动对象。
- 修改字符串字面量。
- 重复释放、错误释放、释放后使用。
- 重叠区域调用 `memcpy`。
- `printf`/`scanf` 格式与实参类型不匹配。
- 把非法值传给 `ctype` 函数。
- 同一完整表达式中对标量对象进行无顺序的冲突访问。
- 违反 `restrict` 契约。
- 多线程中对普通对象发生数据竞争。
- 通过不允许的类型别名访问对象。

## 优化与调试工具链

### 严格警告

```bash
cc -std=c17 -O2 -Wall -Wextra -Wpedantic -Wconversion -Wshadow \
  -Wstrict-prototypes -Wmissing-prototypes -Wvla \
  solution.c -o solution
```

警告不是标准证明，但能快速发现：

- 隐式符号转换和窄化。
- 变量遮蔽。
- 缺少原型。
- 可疑控制流和格式字符串。
- VLA 依赖。

### Sanitizer

```bash
cc -std=c17 -O1 -g3 \
  -fsanitize=address,undefined -fno-omit-frame-pointer \
  solution.c -o solution
```

- AddressSanitizer 常用于越界、use-after-free 等内存错误。
- UndefinedBehaviorSanitizer 覆盖部分未定义行为，例如某些溢出、非法移位和错误对齐。
- Sanitizer 没有报错不等于程序没有未定义行为，也不替代边界证明。

### 优化级别差异

如果代码只在 `-O0` 正常、在 `-O2` 异常，首先怀疑：

- 未定义行为。
- 未初始化读取。
- 严格别名或对齐问题。
- 数据竞争。
- 依赖未指定求值顺序。

不要用关闭优化作为最终修复。

## C23 边界

C23 对语言和库做了多项更新，但考试环境通常不会仅凭“当前年份”自动支持。答题前检查：

- 编译命令中的 `-std=`。
- 平台编译器版本。
- 题目是否允许扩展。

除非环境明确支持，不依赖 C23 新关键字、`nullptr`、新的预处理能力或新库接口。复习 C23 时应对照最新 WG14 文档，而不是把 C++ 同名特性直接套入 C。

## 考场决策顺序

1. 从约束确定复杂度和最大中间值。
2. 确定数组容量、索引类型和和/积的类型。
3. 明确区间约定、哨兵和不可达状态。
4. 先写正确的简单版本，再做常数优化。
5. 每个指针写清所有权和有效期。
6. 每个库函数确认参数契约、返回值和失败路径。
7. 用最小、最大、重复、空和退化输入走一遍。

## 编程技巧入口

语言规则告诉你“什么代码有定义”，但考试时更需要一套稳定的写法来降低失误率。[C语言专业编程技巧清单](../c-professional-programming-checklist/) 从 Princeton、NASA、Power of Ten、Modern C、comp.lang.c FAQ、Harvard CS61 和 Linux kernel coding style 中提炼出可执行习惯：

- 让代码可机械检查，而不是只靠人工目测。
- 保持控制流和函数边界简单。
- 明确资源申请、释放和错误清理路径。
- 少用宏，且宏必须像完整语法单元。
- 不把平台风格误当 ISO C 标准保证。

## 自测问题

1. 为什么 `sizeof(array) / sizeof(array[0])` 在函数形参中通常失效？
2. `int` 与 `unsigned int` 比较时，负数为什么可能变成大正数？
3. `i = i++ + 1` 的问题为什么不是“最终值不确定”，而是未定义行为？
4. `realloc` 失败和成功时，原指针各自处于什么状态？
5. 为什么 `return *(int *)a - *(int *)b;` 不是可靠的 `qsort` 比较器？
6. 为什么 `volatile` 不能解决线程间数据竞争？
7. 何时可以形成尾后指针，何时可以解引用？
8. 为什么含 padding 的结构体不能用 `memcmp` 判断语义相等？
9. 为什么 `getchar()` 必须先保存在 `int` 中？
10. 为什么 `memcpy` 可用于复制对象表示，而不应通过不兼容指针直接重解释？
11. `calloc(n, size)` 与 `malloc(n * size)` 在溢出处理和初始化上有什么区别？
12. BFS 为什么通常在入队时标记访问？
13. 0/1 背包为什么倒序遍历容量？
14. `const int *` 与 `int *const` 分别限制什么？
15. 哪些行为属于 ISO C，哪些只是 POSIX 或 GNU 扩展？
