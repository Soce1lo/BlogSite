# STM32 嵌入式部件全景速通计划

> 这是一份尚未公开的项目草案。实际开始学习后，只有上板现象、测量证据、失败与恢复或明确取舍已经形成，才会重组为面向读者的公开内容；当前路线和验收条件不作为成果发布。

## 项目定位

这是一个面向已有 C 或嵌入式经验者的 STM32F103 速通项目。目的不是从零学习语法，也不是机械复刻教程中的所有例程，而是把一套完整入门教程当作嵌入式开发的部件地图：快速走过启动、输入输出、时间、中断、采集、搬运、通信、电源、可靠性和存储，再用一个综合数据链路把它们串起来。

配套课件共 207 页，源码目录包含 39 个实际 Keil 工程。项目把它们压缩为 **7 次、每次 2～3 小时，总计约 16～20 小时** 的集中学习。每类部件选择一个代表性实验上板，其余例程只做实现对照或快速通读。

项目当前处于进行中。编译、下载和 LED 运行的最小环境已经确认；下文描述的是计划和验收标准，不把尚未完成的实验写成成果。

## 三种学习深度

| 层级 | 方法 | 目的 |
| --- | --- | --- |
| P0 主实验 | 真机运行，修改一个参数或故障条件，保存观测结果 | 建立硬件、代码与现象之间的因果关系 |
| P1 对照实验 | 比较两个工程的初始化和主路径，必要时才都上板 | 看清轮询/中断、CPU/DMA、软件/硬件外设的取舍 |
| P2 快速通读 | 阅读课件、框图和源码差异，回答新增了哪个机制 | 跳过重复应用场景，不遗漏系统部件 |

每次学习只保留一页结论：部件位置、初始化依赖、数据或控制路径、观测方法、失败与恢复、性能预算。

## 7 次集中学习

| 次数 | 部件范围 | 代表实验 | 本次产出 |
| ---: | --- | --- | --- |
| 1 | 启动、工程结构、GPIO、输入输出与调试 | 工程模板、按键控制 LED、OLED | 从复位到 `main`、RCC、GPIO 和观测端的最小系统图 |
| 2 | NVIC/EXTI、定时器、PWM、输入捕获 | 外部中断、定时中断、输入捕获 | 中断优先级、定时器时基与波形测量时间线 |
| 3 | ADC、DMA 与缓冲区 | DMA+ADC 多通道；对照 CPU 搬运 | `ADC → DMA → RAM` 数据流和首次性能基线 |
| 4 | USART、帧格式与数据包 | 串口文本数据包 | 接收状态机、超时和日志边界 |
| 5 | I2C、SPI 与外部器件 | 硬件 I2C 读传感器、硬件 SPI 读写 Flash | 总线事务、错误恢复和软硬件实现对照 |
| 6 | RTC、低功耗、看门狗、内部 Flash | RTC、Stop、IWDG、内部 Flash | 复位域、掉电保持、唤醒、恢复和持久化状态图 |
| 7 | 综合数据链路与性能闭环 | `TIM → ADC+DMA → 缓冲区 → UART` | 可持续运行、可测量、可回归的数据链路 |

这 7 次可以连续完成，也可以在 7～14 天内隔天完成。遇到工具或接线问题时，只修复当前阻塞点，不把整个项目重新扩张为长期初学课程。

## 每次实验只问六件事

1. 这个外设在 CPU、总线、引脚和内存之间处于什么位置；
2. 初始化依赖哪些时钟、引脚映射、寄存器、NVIC 或 DMA；
3. 正常路径怎样运行，软件从哪里观测；
4. 改变频率、缓冲区、优先级、超时或输入后，现象为何变化；
5. 时钟未开、标志未清、地址错误或外设无响应时，先检查哪里；
6. 它占用了多少周期、带宽、RAM、Flash 或实时预算。

这样的提问方式比“例程能不能跑”更接近真实嵌入式系统：一个部件必须同时具备初始化、数据路径、状态、错误、恢复和预算。

## 部件地图

| 系统问题 | 教程部件 | 需要形成的认识 |
| --- | --- | --- |
| 系统怎样开始运行 | 启动文件、CMSIS、时钟、工程结构 | 从复位到 `main` 的依赖和边界 |
| 软件怎样接触物理世界 | GPIO、按键、LED、OLED | 电气模式、输入输出和最小观测入口 |
| 事件怎样及时到达软件 | EXTI、NVIC、定时器 | 轮询、中断、优先级、共享状态和截止时间 |
| 连续信号怎样变成数据 | ADC | 采样时间、通道、精度和吞吐 |
| 数据怎样以更低的 CPU 成本搬运 | DMA | 方向、宽度、计数、缓冲区生命周期和并发 |
| 字节流怎样变成协议 | USART | 帧、缓冲、状态机、超时和日志边界 |
| 板上器件怎样通信 | I2C、SPI | 事务、时序、ACK/片选、超时和总线恢复 |
| 时间和状态怎样跨过空闲与掉电 | RTC、BKP、PWR | 时钟域、保存内容、唤醒源和恢复代价 |
| 软件失控后怎样恢复 | IWDG、WWDG | 故障检测、喂狗合同和复位原因 |
| 配置怎样持久化 | 内部 Flash、外部 Flash | 擦写粒度、寿命、busy 和掉电风险 |

## 性能调优闭环

项目只做一个完整闭环，避免为每章制造孤立的微基准。综合链路固定为：

```text
TIM 固定节拍 → ADC 多通道采样 → RAM 缓冲区 → UART 分包发送
                       │
                       └─ 基线：CPU 轮询搬运
                          优化：DMA 批量搬运
```

闭环有八步：

1. 固定采样频率、通道数、批大小、系统时钟、工具链和优化级别；
2. 以每批 CPU 活跃周期为主指标，同时记录最大时延、丢样、吞吐、Flash 和 RAM；
3. 用 DWT `CYCCNT` 校准计数器读取开销，被测区间不打印、不停断点；
4. 轮询版本在同一负载下重复至少 30 次，保存最小值、中位数和最大值；
5. 判断成本来自等待转换、逐样本搬运、发送粒度还是日志；
6. 首选只把轮询搬运改为 DMA 批量搬运，不同时修改其他变量；
7. 用同一负载重复测量，并回归数据、丢样、最大时延、内存和错误路径；
8. 证据支持且代价可接受则保留，否则回退、修正假设或停止。

如果没有电流表或功耗分析仪，只报告 CPU 活跃时间和唤醒延迟，不把它们直接写成实际能耗收益。

## 综合链路验收

首轮使用以下试验目标，不把它们包装成通用产品指标：

- 以 100 Hz 或本轮固定频率连续运行 10 分钟，样本序号无缺口；
- 最坏一次处理路径小于采样周期，UART 输出不进入被测区间；
- DMA 缓冲区没有越界、静默覆盖或半包数据；
- 主动制造一次错误输入或外设超时，能够观测失败并进入明确的恢复或停止路径；
- 优化前后使用相同负载完成至少 30 次测量，并同时回归功能、时延、内存和错误路径；
- 最终明确写出保留、回退、继续验证或停止。

传感器、外部 Flash、RTC、看门狗和低功耗可以在主链路完成后继续接入，但不是速通项目的阻塞项。先完成一条清晰、可验证的数据链路，再扩展系统复杂度。

## 完成标准

- 207 页课件全部归入部件地图，没有遗漏章节；
- 7 次集中学习完成，约 14 个代表性工程真实上板，其余示例完成对照或快速通读；
- 能闭卷画出启动、输入输出、中断、时间、采集、搬运、通信、电源、恢复和存储的关系；
- `TIM → ADC+DMA → 缓冲区 → UART` 连续运行通过验收；
- 至少完成一次从基线、定位、单变量优化到回归和取舍的闭环；
- 明确 STM32F103 的结论不能直接外推到带复杂 Cache、MMU、多核或完整 PMU 的平台。
