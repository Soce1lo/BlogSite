# 卡码网设计模式编程课学习计划

本项目属于长期的软件开发能力建设，与 [LeetCode C 语言训练](../leetcode-c-language-training/) 分别训练软件设计判断和算法实现能力。

这项学习不是把 GoF 的 23 个名称逐一翻译成 C 的 `struct` 和函数指针。那样很容易把大量样板代码误当成设计能力，也会遮住一个更重要的问题：当前系统里究竟有什么变化值得被隔离。

我会先理解课程中的标准表达，再从普通函数、`enum`、表驱动和直接组合开始。只有这些最小方案无法清楚地处理接口稳定性、行为替换、资源生命周期或对象协作时，才尝试在 C 中引入更明确的模式结构。

## 我想借它练什么

C 缺少类、继承和语言级动态派发，但并不缺少变化、边界和资源管理问题。一次真正有价值的练习，需要回答：

- 谁持有对象，谁只借用对象，谁负责销毁；
- 变化发生在创建、算法、状态、接口适配还是事件通知；
- 函数指针、上下文和实际对象的生命周期是否一致；
- 不使用模式时，最简单的实现是什么；
- 引入模式后，得到的隔离是否值得额外的间接层和测试成本。

## 本轮范围

- 对 23 种模式完成意图、适用前提、反例与最小 C 替代方案的判断；
- 重点实作工厂方法、适配器、代理、外观、观察者、策略、命令、状态和责任链这 9 种模式；
- 其余模式先完成概念对照，只有真实变化点需要时才增加实作；
- 最后用 2–3 种模式组合一个小系统，记录至少 2 个拒绝使用模式的理由。

## 完成标准

- 能独立解释 23 种模式的意图、协作、适用与不适用场景，并区分易混淆模式；
- 9 种重点模式均有 C11 实现、页面样例与 ASan / UBSan 验证，并明确接口和对象生命周期；
- 每个重点模式记录一个实现错误、一个设计取舍和一个闭卷问题，完成 D+7 复习；
- 9 种重点模式形成经人工复核的模式笔记，其余模式进入创建型、结构型、行为型三篇对比记录；
- 完成综合练习，对比引入模式前后的复杂度、可测试性和可扩展性。

在线判题如发生则记录真实回执；全部在线 Accepted 与 D+30 复习不作为本轮完成条件。

## 不把计划当成果

23 种模式是学习地图，不是 23 篇公开文章的待办清单。项目内部会保留课程路线、当前练习和验证证据；公开页不镜像阶段日期、完成数量或尚未发生的综合练习。

真正能形成输出的，应当是一次已经完成的设计判断：例如，为什么一个驱动适配需要适配器而普通转换函数已经足够；为什么一个状态机应该保持为 `enum` 加显式转移；或者为什么某个函数表反而让生命周期和错误路径更难审查。

## 输出的最低门槛

每一篇后续公开笔记都应至少包含：

1. 具体要处理的变化或约束；
2. 不使用模式时的最小方案；
3. C 中的接口与生命周期取舍；
4. 可运行样例、测试或其他真实验证；
5. 一个保留或拒绝该模式的明确结论。

这样，“拒绝使用模式”也会成为有效成果，而不是没有完成课程的借口。

## 项目边界

这项训练低于 LeetCode C 语言训练的优先级。公开写作也不会占用当前实现任务；只有当一次练习已经形成自己的问题、证据和判断时，才会从项目中长出独立的笔记或文章。
