# C 语言设计模式学习计划

## 项目目标

这个项目以[卡码网设计模式编程课](https://kamacoder.com/course.php?course_id=14)的 23 道题为主线，但目标不是机械做完 23 题，也不是用 C 模仿一套残缺的类系统。

我希望完成四个层次的学习：

1. 能说清每个模式要解决的设计问题、关键角色和协作关系；
2. 能判断它什么时候有价值，什么时候只会增加复杂度；
3. 能把面向对象语言中的角色转译为 C 的结构体、函数指针、组合关系和生命周期管理；
4. 能通过独立实现、页面样例、Sanitizer 和复习问题验证理解，而不是照着参考代码重写一遍。

## 为什么要专门做一次 C 转译

GoF 设计模式的常见讲解通常以类、继承、接口和虚方法为主要表达方式。C 缺少这些语言级构造，却仍然需要面对接口稳定性、行为替换、资源包装、对象协作和状态管理等设计问题。

这意味着学习重点不应是“怎样在 C 里伪造一个类”，而应该是：

- 哪个变化点值得被隔离；
- 普通函数、`enum` 或数据驱动是否已经足够；
- 什么时候需要函数指针和上下文对象；
- 谁创建、持有、借用和销毁资源；
- 复杂结构是否真的换来了更清晰的扩展边界。

每道题都会先比较“不使用模式时最简单的 C 写法”。只有模式确实改善了变化隔离、生命周期或接口管理，额外复杂度才有意义。

## 每题学习闭环

每个模式用一次 60–90 分钟的首次学习建立骨架，不边看参考代码边照抄。

1. **识别问题**：先读题面，写下“不用这个模式时，哪个设计约束会被破坏”。
2. **吸收课程**：读完讲解后关闭页面，用自己的话重述意图、角色、协作流程、适用场景和反例。
3. **画出关系**：用简单关系图表达对象、调用和所有权，不只记定义。
4. **完成 C 转译**：明确类、接口、继承和虚方法分别怎样转换为 `struct`、组合、函数指针、创建/销毁函数或文件作用域状态。
5. **独立实现**：完成包含 `main` 的 C11 标准输入输出程序，再回看参考实现。
6. **真实验证**：运行页面样例与 Sanitizer；如果执行在线提交，就记录真实回执。
7. **完成复盘**：记录一个实现错误、一个设计取舍和下次闭卷要回答的问题，安排 D+1、D+7 和 D+30 复习。

## C 转译检查表

- 角色是否真的需要动态多态，还是普通函数和 `enum` 就足够；
- 函数指针、上下文指针和实际对象的生命周期是否一致；
- 谁创建、谁销毁、谁持有，谁只是借用对象；
- 是否为了外观上的“模式结构”引入了全局可变状态；
- 多线程场景下的初始化、共享状态和回调是否安全；
- 不使用模式的更简单实现是什么，当前复杂度是否值得。

## 每个模式的完成标准

### 理解

- 不看课程，能用一分钟说清模式意图、角色和一次完整协作流程；
- 能说出一个适用场景、一个不适用场景和一种更简单的替代方案；
- 能区分至少一个易混淆模式，说明它们变化轴或意图的不同；
- 能指出题目为什么要求这个模式，而不只是背定义。

### C 设计与实现

- 程序保持为完整的 C11 标准输入输出实现；
- 角色、组合、回调、创建和销毁合同有明确说明；
- 能解释 C 实现与 Java、C++ 等语言实现的表达差异；
- 页面样例、AddressSanitizer 与 UndefinedBehaviorSanitizer 均通过；
- 如果已在线提交，以真实回执作为最终结果。

### 知识沉淀

- 完成一篇与题目解答分离的模式学习笔记；
- 笔记主体是个人重述、比较、决策和错误，而不是课程内容搬运；
- 完成 D+1 和 D+7 闭卷复习后，才把项目进度设为“已掌握”；
- D+30 复习通过后，再判断这篇笔记是否已经足够稳定。

## 后续公开记录

随着 23 道题逐步完成，我会为每个设计模式发布一篇独立学习笔记。每篇笔记都会回答：

- 这个模式隔离的变化是什么；
- 不使用模式时，最简单的实现是什么；
- 它在 C 中怎样通过结构体、组合、函数指针和生命周期表达；
- 实现时遇到了什么错误，怎样验证；
- 它与相近模式有什么区别，在哪些场景下不应该使用。

项目页维护路线、总体进度和模式索引；单模式笔记保留可复用理解。完成并发布的学习笔记会陆续从这里关联出去。

## 课程收尾

23 道题完成后，我不会用第 24 道孤立练习收尾，而会选择一个熟悉的小系统：

- 先画出不使用模式的最小设计；
- 选择 2–3 个真正有价值的模式完成组合设计；
- 明确拒绝至少 2 个不合适的模式，并记录理由；
- 用一页决策记录比较前后复杂度、可测试性和可扩展性。
